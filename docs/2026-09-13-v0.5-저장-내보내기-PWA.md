# 2026-09-13 · v0.5 — 저장 · 내보내기 4종 · PWA

아들이 왔을 때 "열어서 바로 보고, 종이로 뽑고, 홈 화면에 두는" 것까지. 귀가 필요 없는 마지막 묶음.

## 1. 만든 것

| 파일 | 역할 |
|---|---|

## 2. 결정

- **원본 오디오를 통째로 저장한다** (5MB wav 기준 문제 없음). 재생 버퍼를 저장하는 것보다 작고, 다시 디코드가 0.3초라 그럴 필요가 없다. 72MB mp4 는 미확인.
- **같은 파일을 다시 열면 새 프로젝트**가 생긴다. 이름으로 합치지 않는다 — 다른 녹음이 같은 이름일 수 있어서. 목록에서 지우면 된다.
- **저장은 마지막 저장본과 같으면 안 한다** (JSON 비교). 처음엔 "첫 렌더 건너뛰기" 플래그였는데 StrictMode 가 효과를 두 번 돌려 빈 저장이 생겼다.
- **PDF 는 브라우저 인쇄로.** 직접 PDF 를 만들지 않는다(기획서 8장 "SVG→인쇄"). 아이패드는 공유 → 프린트 → 핀치로 PDF.
- **MusicXML 은 되읽지 않는다.** 편집은 앱 안(오버레이)에서만.

## 3. 확인한 것 (크로미움)

- 분석 후 IndexedDB 에 오디오 5.3MB + f0 5168 프레임 저장됨
- 뒤로 → 최근 목록 → × 지움 → 열기: **101ms** 에 악보까지 표시
- BPM 60→90 바꾸면 "저장됨", 다시 열면 90 유지
- 내보내기 4종 모두 결과물 생성: MusicXML 23KB(헤더 확인), MIDI 1.9KB(`MThd`), PNG 229KB, 인쇄 HTML 에 SVG 1개·제목·메타
- 인쇄 레이아웃: A4 가로 폭에 마디 2개씩 접힘, 줄 폭 채움 (캡처 확인)
- `pnpm build`: `manifest.webmanifest`, `sw.js`, 프리캐시 16개

## 4. 확인 안 한 것

- **홈 화면 설치는 HTTPS 에서만** 된다(localhost 예외). 아직 호스팅이 없어서(git remote 없음) 실기기 설치는 못 봤다.
- 사파리에서 `<a download>` 가 공유 시트로 뜨는지, 인쇄 새 창이 팝업 차단에 걸리는지
- 큰 파일(72MB mp4) 저장 용량
- MusicXML 을 MuseScore 등에서 열어 보지 않았다
- 실행 취소 없음 (v0.3 부터)
