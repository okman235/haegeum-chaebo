# 2026-09-13 · v0.3 — 리듬 양자화 + 음표 편집 (마디 맞는 악보)

v0.2 의 노트 열에 격자를 깔아 마디·음길이·쉼표·붙임줄이 있는 악보로 만들었다. 자동 박 추적은 없다(기획서 6.2).

## 1. 만든 것

| 파일 | 역할 |
|---|---|
| `app/src/audio/rhythm.ts` | 장단 프리셋(`JANGDAN`), 격자(`Grid`: 장단·8분/16분·BPM·첫 박), `quantize` → 마디별 `ScoreNote` |
| `app/src/components/RhythmBar.tsx` | 장단 선택 · BPM 입력 + **탭 템포**(최근 8번 평균) · 격자 8/16분 · **첫 박 = 현재 위치** |
| `StaffView` (다시 씀) | 마디마다 Stave, 첫 마디에 음자리표·박자표, 쉼표, 점음표, 박 단위 빔(3/8 또는 1/4), 마디 넘는 음은 붙임줄 |
| `CurveView` | 박선(희미) · 마디선(청록) · 마디 번호. 칸이 6px 보다 촘촘하면 박선 생략 |
| `TuningBar` | 선택 음 편집: ♯ ♭ · 시작 ◀▶ · 끝 ◀▶ (격자 한 칸) · 지움 |
| `notes.ts` | `NoteEdit` 오버레이 + `applyEdits`. 열쇠는 원 노트의 시작 시각(ms) |

## 2. 결정

- **BPM 의 "박"은 장단의 박이다.** 12/8·18/8 은 점4분음표(8분 3개), 12/4·4/4 는 4분음표. 사용자가 세는 박과 맞추려고.
- **격자 기본은 8분음표.** 16분은 선택. hg_180_240(중중모리, ♩.=60 가정)에서 8분 격자면 붙임줄 0, 16분이면 5개.
- **첫 박 앞의 소리는 못갖춘마디**로 남긴다 (마디 번호 0, −1, …). 잘라 버리지 않는다.
- **편집은 오버레이.** 원 노트의 시작 시각을 열쇠로 두어, 분할 감도를 바꿔도 같은 자리의 음이면 편집이 남는다. 다른 자리면 조용히 사라진다 — v0.5 저장 때 다시 볼 것.
- **선택은 분할 결과(rawNotes)에 묶인다.** 편집만으로는 안 풀리고, 다시 분할되면 풀린다. (처음엔 편집된 배열에 묶어서 ♯ 누르자마자 선택이 풀리는 버그가 있었다.)
- 박자표 값은 기획서 6.2 의 **기억값** 그대로 (진양조 18/8 · 중모리 12/4 · 중중모리 12/8 · 자진모리 12/8 · 휘모리 4/4). 아들이 고치면 `JANGDAN` 한 곳만.

## 3. 확인한 것 (크로미움, hg_180_240.wav)

- 모든 마디의 칸 수 합 = 마디 길이 (8분·16분 격자 모두, `__score` 로 검사)
- 오선보 음 탭 → ♯ → F5 로 바뀌고 선택 유지 → 지움 → 그 자리가 8분쉼표, 음 205개
- 재생 헤드 20.3s 에서 "첫 박 = 현재 위치" → 그 자리가 1마디, 앞은 −9…0
- 탭 4번(0.5초 간격) → 113 BPM
- HMR 중 `score` 가 없는 순간 StaffView 가 한 번 던졌다(`reading 'bars'`). 새로 열면 안 난다 — HMR 과도기라 두었다.

## 4. 확인 안 한 것

- 사파리·아이패드 (v0.2 와 같은 이유)
- 진양조·중모리처럼 긴 마디에서 마디 폭이 화면을 넘을 때 보기 좋은지
- 편집 취소(undo)가 없다 — 지운 음을 되살릴 길이 없다. v0.5 저장과 함께 넣을 것
