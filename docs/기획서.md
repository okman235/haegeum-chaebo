# 해금 채보앱 기획서 v2

작성일: 2026-09-12 · 상태: 기획회의 2차 반영 (착수 전) · v1 대비 변경: 브라우저 단독 전환, 표기·갈래·음원·사용자 복수화

## 1. 한 줄 정의

**해금 녹음(또는 마이크)을 넣으면 음높이 곡선과 시김새 부호가 붙은 오선보를 브라우저 안에서 자동으로 뽑아 주고, 손으로 다듬어 교재용으로 내보내는 웹앱. 서버 없음, 링크 하나로 아이패드·수강생에게 배포.**

## 2. 확정 결정

| 항목 | 결정 | 메모 |
|---|---|---|
| 악기 | 해금 전용 | 단선율 → f0 추적 |
| 갈래 | 산조·민속악 / 정악 / 창작국악·퓨전 | **조율 프리셋**으로 전환. 기본은 산조 |
| 입력 | 오디오 자동 분석 | 분석은 전부 브라우저(WASM)에서 |
| 음원 | 독주 녹음 / 장구 반주 / 합주 속 해금 / 마이크 실시간 | **음원 모드**로 분기. v1은 독주+장구, 합주·마이크는 이후 |
| 출력 | 오선보 + 음높이 곡선 그래프 | 둘 다 내보내기 대상 |
| 시김새 | 자동 감지 → 부호, 편집기에서 수정 | 임계값 조정 가능 |
| 사용자 | **아들** (제작자인 나 포함). 수강생·지인 배포는 **없음** (2026-09-13 정정) | 설명 없이 쓸 수 있는 한국어 UI |
| 플랫폼 | 정적 웹앱 (PWA) | **기기 셋 다 (2026-09-13): 아이패드·아이폰 사파리 + 맥/PC 크롬.** 따라서 기준은 더 빡빡한 사파리로 잡는다 — 속도는 실시간 5.5배, 입력은 mp4+AAC만. 홈 화면 설치, 오프라인, 녹음 파일은 기기 밖으로 안 나감 |

## 3. 사용 시나리오

**A. 교재 제작 (나)**
녹음 → 열기(설정 없이 기본 프리셋으로 **바로 분석**) → 곡선+오선보 확인 → 상단 칩에서 장단 고르고 재생하며 **박 두드리기**로 빠르기·첫 박 잡기(악보만 재배치) → 편집 → PDF/MusicXML/곡선 PNG 내보내기 → 교재·영상에 삽입.

> 첫 화면은 **파일 불러오기·녹음·최근 프로젝트뿐** (2026-09-13 결정). 빠르기는 듣기 전엔 알 수 없고, 쓰는 사람이 첫 화면에서 막히면 안 되므로 설정은 결과 화면에서 한다.

**B. 아들 자습**
링크로 앱 열기 → 마이크로 자기 연주 녹음 → 곡선에서 농현 폭·퇴성 위치를 눈으로 확인 → 내 채보와 나란히 비교 (v1.x).

| 합주 속 해금 | essentia.js `PredominantPitchMelodia` (다성 음원에서 주선율 추출, 브라우저 빌드에 포함 확인) | v2. 정확도 낮을 것으로 예상. 브라우저 음원분리(Demucs 계열)는 **확인 안 함**, 후순위 |

**사파리 `decodeAudioData` 컨테이너·코덱 판정 (2026-09-13, 아이패드 Safari 26.6 + 맥 Safari 동일 결과. 크롬은 전부 성공)**

| 파일 | 컨테이너 `ftyp` | 소리 코덱 | 사파리 |
|---|---|---|---|
| `.wav` | — | PCM | ✅ |
| `probe_sanjo_aac.m4a` | isom | AAC | ✅ |
| `probe_sanjo_h264_aac.mp4` 79MB | isom | AAC | ✅ |
| 유튜브 원본 `.mp4` 72MB | isom | **Opus** | ❌ EncodingError |
| 화면 녹화 `.mov` 4초 | **qt** | AAC | ❌ EncodingError |
| 위 mp4를 `.mov`로 리먹스 (스트림 동일) | **qt** | AAC | ❌ EncodingError |
| 같은 `.mov`의 ftyp 4바이트만 `isom`으로 바꿔치기 | isom(위조) | AAC | ❌ EncodingError |
| **아이폰 카메라 촬영본 `.MOV` 8초 37MB** | **qt** | AAC 48k 스테레오 (+공간음향 `apac`, 메타 `mebx` 트랙) | ❌ EncodingError |
| 그 촬영본을 `-c copy`로 mp4에 다시 담은 것 | isom | 같은 AAC | ✅ 8초를 0.20s |

같은 스트림이 컨테이너만 바뀌어도 갈리므로 **원인은 코덱이 아니라 컨테이너**(Opus는 별개 원인). ftyp만 고쳐선 안 되니 웹킷이 더 안쪽 구조를 본다 — 고치려면 실제 리먹스(mp4box.js 계열)나 WebCodecs 경로가 필요하다. 맥에 있는 `.mov`는 화면 녹화·공연 촬영본 모두 `qt  ` 브랜드였고, **아이폰 카메라 촬영본도 `qt  `라 실패한다 (2026-09-13 실물로 확인)**. 즉 **아이패드·아이폰으로 찍은 영상은 지금 구조에선 하나도 안 열린다.**

**해결 (2026-09-13): 앱 안에서 직접 푼다.** 변환을 사람에게 시키는 건 답이 아니라, 사파리에도 있는 두 조각으로 우회했다 — mp4box.js(qt 컨테이너 파싱 됨)로 소리 트랙을 뜯고 WebCodecs `AudioDecoder`(사파리에서 AAC·**Opus 둘 다 지원 확인**)로 PCM을 뽑는다. 재인코딩 없음. `decodeAudioData`가 실패할 때만 이 길로 간다 (`app/src/audio/movDecode.ts`, `decode.ts`).

맥 사파리에서 앱 경로 그대로 확인:

| 파일 | 디코드 | 전체(음높이 추적 포함) |
|---|---|---|
| 아이폰 촬영본 8초 `.MOV` | 0.06s | 0.25s |
| 화면 녹화 4초 `.mov` | 0.01s | 0.10s |
| 유튜브 원본 6분 mp4 (Opus) | 1.64s | 47.8s |
| 산조 6분 `.mov` 79MB | 0.92s | 47.2s |

함정: `setExtractionOptions`/`start()`를 `await` 뒤로 미루면 mp4box가 이미 버퍼를 비워 샘플이 한 개도 안 나온다. **`onReady` 안에서 바로** 걸어야 한다.

**딸린 발견**: 같은 맥에서 pYIN 계산이 사파리 7.6배속 vs 크롬 58배속으로 **7~8배 차이**가 난다(6분 음원에 46초 대 6초). 아이패드가 느린 건 기기 탓만이 아니라 엔진 탓도 크다. 최적화 여지가 여기 있다.

## 5. 조율 프리셋

프리셋은 `{기준음 주파수, 조(key), 음역 fmin~fmax, 조표 기본값}` 묶음. 값은 **사용자 기준을 받아 채움** (제 기억으로 하드코딩하지 않음).

| 프리셋 | 비고 |
|---|---|
| 산조·민속악 (기본) | 시김새 감지 임계값도 이 프리셋에 묶임 |
| 정악 | 율명 체계 엄격. 음역·기준음 별도 |
| 창작국악·퓨전 | A4=440 Hz 12평균율 |

프리셋과 별개로 녹음마다 **f0 히스토그램 → 평균율 대비 편차(센트)** 를 추정해 UI에 표시하고 보정값으로 쓴다. 프리셋이 틀려도 보정이 잡아 주는 이중 구조.

## 6. 분석 파이프라인 (전부 브라우저, Web Worker에서 실행)

```
파일 / 마이크
 → Web Audio decodeAudioData → mono Float32 (필요 시 리샘플)
 → essentia.js pYIN → 프레임별 f0 + 유성 확률
 → 조율 보정 (5장)
 → 음 분할: f0 안정 구간 + 에너지/스펙트럼 플럭스 onset → 노트 세그먼트
 → 시김새 감지 (규칙 기반, 6.1)
 → 리듬 양자화: 장단 프리셋 × BPM × 첫 박 → 격자 스냅 (6.2)
 → 노트 모델 JSON → 곡선 뷰 / 오선보 뷰 / 내보내기
```

### 6.1 시김새 감지 규칙 (초안 — 부호 모양은 사용자 교재 관행으로 확정)

| 시김새 | f0 곡선 특징 | 부호(자리 표시자) |
|---|---|---|
| 농현 | 주기적 진동 4~8 Hz, 폭 ≥ 임계 센트 | 파형선 ~~~ (폭·속도로 굵기) |
| 추성 | 세그먼트 끝 상행 활주 | ↗ |
| 퇴성 | 세그먼트 끝 하행 활주 | ↘ |
| 전성 | 짧고 급한 1회 꺾임 후 복귀 | 별도 부호 (확인 후) |

### 6.2 리듬 — 가장 어려운 부분

산조 독주는 루바토가 커서 **자동 박 추적을 v1에서 신뢰하지 않는다.**
- v1: 장단 프리셋 + BPM 수동 + 첫 박 클릭. 벗어난 음은 편집기에서 이동.
- v1.x: 장구 반주 모드에서 타악 onset으로 박 제안.
- 장단별 박자표(제 기억, **확인 필요**): 진양조 18/8 · 중모리 12/4 · 중중모리 12/8 · 자진모리 12/8 · 휘모리 4/4 또는 12/8

합성음은 필요조건이었을 뿐이다. 해금의 배음 많은 음색 + 장구 반주에서 단일 프레임 YIN은 배음에 걸려 옥타브 위로 튄다. **결정: librosa pyin 알고리즘을 JS로 이식**(후보 골 + 베타/볼츠만 확률 + 유성/무성 2층 HMM 비터비, 음역 제한, 22.05 kHz로 리샘플). 검증 잣대: 같은 구간에서 기준과 90% 이상 일치. CREPE(ml5)는 이식이 실패할 때의 대안.
